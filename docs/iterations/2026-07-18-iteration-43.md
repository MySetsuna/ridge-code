- 减法 `invoke_best_of` 标 doc(hidden) 与 iter-42 裁决矛盾;`est_tokens` 合并「provider 层 tiktoken 残留」不存在。

## 做了什么(端到端,gate 全绿)

**`crates/provider` 新 `oauth` 模块**(纯核离线可测 + HTTP 走 `HttpClient` 接缝):
- `Pkce`(S256 = `base64url_nopad(sha256(verifier))`;base64url 手写纯编码,`sha2`/`getrandom` 只做 crypto 原语)、`authorize_url`、`parse_token_response`(`expires_at=now+expires_in`,now 传参)、`OAuthToken{access,refresh,expires_at}::needs_refresh(now)`、`exchange_code`/`refresh`。
- Anthropic 常量(client_id/authorize/token/redirect/scopes/beta/system-identity)集中 `oauth::anthropic_oauth`。
- `AnthropicProvider::new_oauth`:bearer 模式 `Authorization: Bearer` + `anthropic-beta`(去 `x-api-key`)+ system 首块注入 Claude Code 身份。

**`crates/agent`**:
- oauth 存储纯核 `oauth_parse`/`oauth_upsert`/`oauth_get`(`~/.ridge/oauth.json` = `{provider: OAuthToken}`,独立于 config/auth)。
- `main.rs`:`login --claude` → `run_login_claude_oauth`(PKCE→打印授权 URL→**用户浏览器授权,Claude 不碰凭据**→读回贴 `code#state`→`exchange_code`→存 oauth.json 0600→best-effort bearer 校验)。`resolve_claude_oauth_provider`(key 全无回退:读 token→`needs_refresh` 则 `refresh` 落盘→`new_oauth` provider),接进 `main` 分流。

## 依赖(安全原语,非「铁律」外置能力)

新增 workspace `sha2`(S256,crypto 绝不手搓)+ `getrandom`(PKCE 安全随机)。二者基础安全原语,非 RAG/AST/tiktoken 那类外置可装能力;OAuth 是内核 auth 特性,无法做成 skill。base64url 纯编码手写省一依赖。

## 对抗评审战果(正确性门禁)

- **端到端非死脚手架**:与 iter-42 删的 workspace.rs 对照 —— 本轮 `OAuthToken`/bearer provider 有真实生产者(login 流)与消费者(login 的 verify + chat 的 `resolve_claude_oauth_provider`)。
- **纯核 now 传参**:刷新/过期判定不读墙钟,`now_epoch()` 仅运行时取真值 → 验收纯函数、无计时断言(守 loop 铁律)。
- **凭据边界**:token 不进 config.json/NLM/notes;oauth.json 0600;access/refresh 不回显于日志(登录只打印路径);浏览器授权由用户本人做。
- **危险命令拦截不受影响**:OAuth 是鉴权旁路,不碰 run_shell/hook 通道。
- **auth.json landmine 规避**:`auth_upsert` 重建时丢弃对象值,故 OAuth 不塞 auth.json 而用独立 oauth.json;订正 `auth_parse` 陈旧注释。
