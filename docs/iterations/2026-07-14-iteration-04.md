## 3. 「距离 Claude Code 式 CLI」的真实差距(请重点定夺)

架构和 agent 内核到位了,但作为**命令行工具的体验**离 Claude Code 还差这些:

| 差距 | 现状 | 说明 |
|---|---|---|
| **交互式 REPL** | ❌ 一次性(跑一个任务就退出) | Claude Code 是常驻对话循环:多轮对话、追问、纠偏。这是最大的体验差距 |
| **实时流式输出** | 🟡 引擎有 `StreamEvent`,CLI 未接 | Claude Code 边想边显示;ridge 现在跑完才一次性打印 |
| **权限门(permission)** | ❌ 无 | Claude Code 对危险操作(写文件/删除/shell)会先征询;ridge 直接执行,无沙箱无确认 |
| **多轮 tool 结果正确回灌** | 🟡 `to_messages` 把工具结果当 assistant 文本铺,没用 `role=tool`/`tool_result` 块 | 已有 `openai/anthropic::build_request` 能正确构造,但 `build_llm_agent` 没用上 |
| **会话/斜杠命令/配置文件** | ❌ 仅 env 变量 | 无 `~/.ridge/config.toml`、无 `/help` 之类 |
| **思考标签处理** | 🟡 未剥 `<think>` | 实测中 GLM 把 `</think>` 漏进 content(不影响闭环,但输出脏) |
| **MCP 真实传输** | 🟡 自写最小 stdio,未接官方 rmcp | |
| **子任务并行 / 沙箱 / TUI** | ❌ | 见既有 backlog |
