# Iteration 22 —— TUI 交互专轨(首刀:修「滚动即拒绝」根因)

> 本地记录(迭代记录不再上传 NLM)。

- **日期**: 2026-07-17
- **触发**: 用户「启 TUI 交互专轨」。iter-21 押后的 TUI 重构开轨,先修唯一正确性 bug。
- **一句话**: NLM notes 头号交互痛点「一滚动就拒绝」的根因,是审批态下除 `y`/`Enter` 外一切键落 `_ => 拒绝`;以模态决策纯函数修根因,滚动看 diff 不再误拒。

## 根因(`crates/agent/src/tui.rs` 事件循环)
```
if let Some(request) = pending.take() {   // ← 任何键都先 take 消费
    match key.code {
        Char('y') | Enter => 批准,
        _ => 拒绝,                          // ← ↑↓/PgUp/PgDn 落此 = 滚动即拒绝
    }
}
```

## 做了什么
- **模态决策纯函数** `approval_action(KeyCode) -> ApprovalAction{Approve,Reject,Scroll(i16),Ignore}`:`y`/`Y`/`Enter`→批准;`n`/`N`/`Esc`→拒绝;`↑↓/PgUp/PgDn`→`Scroll(±)`;余键→`Ignore`。
- **事件循环审批分支重写**:`pending.is_some()` 时按决策走 —— 批准/拒绝才 `pending.take()` 消费并回信;**滚动/忽略不消** pending(`SyncSender::send(&self)` 允许 peek),滚动只动 `ui.scroll`(`apply_scroll` u16 饱和)。
- **文案对齐**:审批 modal 与 `/help` 由「任意其他键: 拒绝」→「y/Enter: 批准 · n/Esc: 拒绝 · ↑↓/PgUp/PgDn: 滚动看详情」(此前文案本身在教用户踩 bug)。

## 测试状态(确定性验证 = checker)
- `cargo test --workspace` **全绿**:bin **6→8**(+2:`approval_scroll_keys_do_not_reject` 滚动键判 `Scroll` 非 `Reject`、字符/退格判 `Ignore`;`apply_scroll_saturates` 上下界饱和不 panic)。agent lib 68 不变。
- clippy `-D warnings` 净、fmt 净。

## 设计要点
- 决策抽为**纯函数**(`KeyCode → ApprovalAction`),与渲染/IO 解耦 → 可单测、无计时抖动(避开 TUI 交互「难无抖测」的老问题:把可判定的**状态转移**从渲染里剥出来测)。
- 不改安全语义:危险命令仍需显式 `y` 批准,默认不放行;只是「滚动」不再被误当拒绝。
