## 做了什么(全在 `crates/agent/src/lib.rs`)

### ① 闭合 iter-17 诚实边界:`edit_file`/`apply_edits` 编辑臂约束守卫
- 缺口:iter-17 只拦了 `write_file`(空写)+ `run_shell`(rm/截断),但 `edit_file(path="tests/x", old="<测试代码>", new="")` 可把测试内容替换为空 = 删测试 → 绕过守卫伪造 CI 绿。
- 修:新增纯函数 `constraint_guard_edit(path, old, new)` —— 受保护路径 + `old` 非空 + `new` 空白 = 纯删除 → 拦。接进 `edit_file` 臂(jail 后)与 `apply_edits` 臂(每个 edit 逐一查,任一命中整批拒,合原子性)。
- 词法级、纯函数、可单测。**改断言等内容级语义篡改**(`new` 非空)本轮不判 —— 诚实标为深度问题(YAGNI)。

### ② P1 `HaltReason::ContextRot`(上下文腐烂)
- 判据:按 `to_messages` 同口径压缩后,历史估算 token(`est_tokens`)仍 > `CONTEXT_ROT_TOKENS`(= 2× `AUTO_COMPACT_TOKENS` = 12000)→ 单条巨消息压不掉(如塞进巨型工具输出),继续只烧预算/降智。
- `context_rotted(&AgentState)` 纯函数,复用 `compact_history`。**定位为终态诊断重标签**(不进 `must_stop` 热路径 —— 需算压缩,而腐烂上下文本就烧 token 快、很快触 budget/step_cap;O(1) 热路径纪律)。喂 signal 复利:失败 run 自动落 `context_rot` 信号。

### ③ P1 `HaltReason::CircuitBroken`(熔断)
- 与 `stall` **正交**:`stall` 认「工具输出与上轮**相同**」;报错内容**每轮不同**时 stall 归零、永不触发。`err_streak` 认「输出是错误」,连错累计。
- 新增 `AgentState.err_streak` 字段 + `Patch::SetErrStreak` reducer,在 act 循环紧邻 stall 计数处回填(`is_error_observation(&obs)` → +1 否则清零)。`MAX_ERR_STREAK=5`。
- `circuit_broken(s)` 接进 `must_stop` → **早停**(早于回合上限),防无人值守 `--every` 循环持续失败烧预算。
- 单一真相:抽 `is_error_observation(obs)` 纯函数,`durable_updates` 与熔断计数共用,免判据漂移。

### 停机原因优先级(`halt_reason`,更根因/更具体者优先)
`approved` > `budget` > `constraint_breach` > `context_rot`(结构性根因)> `circuit_broken`(连错症状)> `stall`(输出停滞)> `step_cap`(通用耗尽)> `unverified`。同为失败终态时给最有诊断价值的标签,喂 signal 复利。
