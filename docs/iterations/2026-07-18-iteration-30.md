# Iteration 30 报告 —— 输入 wcwidth 光标(正确性修复)

> maker = 用户需求原文第 4 条。checker = CONTRACT-iteration-30。承 iter-29 后续,消灭用户中文输入必踩的「光标不落末端、偏左」根因。

## 做了什么(只碰 tui.rs + Cargo + docs)

- 引 `unicode-width = "0.2"`(workspace + agent;TUI 显示层标准宽度表,ratatui 本就间接依赖)。
- `char_cells(c)` / `str_cells(s)`:wcwidth 显示单元格宽辅助(CJK/emoji=2、零宽/控制=0)。
- `InputState::cursor_display_col() -> (row, display_col)`:真光标据此落点;**逻辑光标 `cursor` 仍是字符序不变**,只在渲染换算处用显示宽 —— 最小面、零回归。
- 收口三处旧 `.chars().count()` 显示宽误用:真光标 x(`row_col`→`cursor_display_col`)、`wrapped_rows` 折行(CJK 不再低估行数致边框撕裂)、补全浮窗宽(`str_cells`)。
- 删 `tui.rs:437` 的 ponytail 妥协注(「CJK 按 1 格计,偏差可容」已兑现)。

## 测试状态(确定性验收,全达成)

`cargo test --workspace && cargo fmt --all --check && cargo clippy --workspace --all-targets -- -D warnings` 全 **exit 0**。新增 `wcwidth_display_columns`:`char_cells('你')==2`、`str_cells("ab你好")==6`、`cursor_display_col("你好a")==(0,5)`(左移后 (0,4))、多行 `"你\nb"`→(1,1)、`wrapped_rows("你你你",4)==2`(旧口径误判 1 行)。纯函数,零计时/PTY。

## 对抗评审战果(正确性门禁)

- **最小面修复**:只动「显示宽换算」处,`cursor` 字符序语义与所有插删/移动方法零改动 → 无回归风险。
- **概念放对层**:`unicode-width` 是 TUI 显示层纯数据宽度表,非「内核精简铁律」(squeez/RAG/AST/tiktoken)所禁的外置计算能力;手搓 Unicode 宽度表反而更烂。判可引。
- **验收纯函数化**:不断言「屏幕上光标像素位置」(需 PTY),只断言 `cursor_display_col`/`str_cells`/`wrapped_rows` 的纯数据输出。
