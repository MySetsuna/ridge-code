# Iteration 34 报告 —— 地址越狱开关 + 状态栏标红(安全放宽须显眼)

> maker = 用户需求「允许地址越狱,但要在状态栏标红」。checker = CONTRACT-iteration-34。安全语义一等关切。

## 做了什么

- **进程级开关**:lib.rs `static ALLOW_JAILBREAK: AtomicBool`(默认 **关**)+ `pub set_allow_jailbreak`/`allow_jailbreak`。与 `jail` 已读的进程级 cwd 同层,不动 `execute_tool_call` 签名及其所有调用点/测试。
- **jail 决策纯函数化**:`jail(path) = jail_guard(allow_jailbreak(), path)`;`jail_guard(allow, path)`:`allow → Ok`,否则原 cwd 子树钳制。**只放宽 cwd 子树** —— 危险命令硬拦截、受保护路径(tests/.git)守卫、只读模式全不碰(`run_shell` 臂不经 jail;`is_dangerous_command`/`constraint_guard_*` 独立在前)。
- **config**:`Config.allow_jailbreak: Option<bool>`;`CONFIG_KEYS += "allow_jailbreak"`,`config_set` 归 bool。main 启动 `agent::set_allow_jailbreak(cfg.allow_jailbreak.unwrap_or(false))`。
- **TUI**:`/jailbreak [on|off|(空=查状态)]` 会话内实时切 + 红/绿 note(默认不持久化 —— 新会话默认锁死更安全;持久化提示走 `/config set allow_jailbreak true`)。顶状态栏 `draw` 读 `agent::allow_jailbreak()`,开则 `RidgeCode` 徽标后插**红底黑字 `⚠越狱`** span。`/help`、`SLASH_COMMANDS` 补 `/jailbreak`。

- `jail_blocks_write_outside_cwd`(既有)**仍绿** —— 证全局默认关且无测试污染(并行安全)。
- `dangerous_shell_command_is_blocked`/`constraint_guard_*`(既有)仍绿 —— 证越狱不碰其它守卫。

## 对抗评审战果(正确性 + 安全门禁)

- **安全默认关 + 显眼红标**:开关默认 false,开启时红底徽标一眼可见 —— 契约硬指标(二者缺一即不通过),达成。
- **放宽面最小**:只 cwd 子树写一条;删除类灾难命令、清空测试(奖励黑客)、只读模式**全不受影响**,深度防御其余层完好。
- **并行测试安全**:决策抽 `jail_guard(bool,...)` 纯函数测,全局 AtomicBool 不在任何测试里翻转 → 不污染并行跑的 `jail_blocks_write_outside_cwd`(此隐患已在契约点名并规避)。
- **概念放对层**:开关是进程级运行时状态(同 cwd 层),非引擎/图概念;`execute_tool_call` 签名零改。
