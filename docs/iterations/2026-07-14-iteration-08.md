## 1. 驾驭工程:从「只能整文件覆写」到「探索-精准编辑」

之前 agent 的工具只有 `read_file`(整读)/ `write_file`(整覆写)/ `run_shell`。改一行也得把整文件吐回来 —— 费 token、易丢内容、大文件直接爆上下文。这是「不像 Claude Code」最硬的一块。本轮补齐(全 std,跨平台):

- **`edit_file(path, old, new)`** —— Claude Code 的 Edit 语义:只替换**唯一**匹配,0 处或多处都报错,逼模型带足够上下文保证唯一,天然防误改。
- **`read_file` 支持 `offset`/`limit`** —— 大文件按行区间读,不必整吞。
- **`search(pattern, path, glob)`** —— 递归 glob(`*.rs`)+ 子串匹配,跳过 `target/.git/node_modules`,返回 `路径:行号:内容`。**Windows 没有 grep**,`run_shell("grep …")` 不可移植;这是 agent 找代码的可移植接缝。命中上限 200 行防爆。
- BASE_SYSTEM 引导:「改已有文件优先 edit_file 而非整覆写;先 search / 分段 read 再改」。

## 2. 用户交互:权限门从「盲批 JSON」到「看着 diff 批准」

之前有副作用的工具审批,detail 是生 `arguments.to_string()`(一坨 JSON),用户根本看不清要改什么。本轮 `preview_call`:

- `edit_file` → 渲染 `-/+` diff(旧行 `-`、新行 `+`),用户**看着改动**决定 y/N。
- `write_file` → 路径 + 行数/字节规模;`run_shell` → 命令原文。
- `search` / `read_file` 归为只读工具,**不再打扰**用户审批。

## 3. 实测(智谱 GLM-4.5-air,零改代码)

`ridge "把 config.rs 里默认的 port 从 8080 改成 9090,只改这一处"`:
模型自主走 **`search`×2 → `read_file`×2 → `edit_file`×1、零 `write_file`**,单行精准改 `8080→9090`,其余原样不动,`approved=true`。trace.json 如实记录工具链。这正是 Claude Code「先探索、后精准编辑」的闭环,用真实模型跑通。
