# Iteration 46 报告 —— 外置沙箱包裹 seam(合「外置能力不进内核」铁律)

> maker = 用户(「都做」之三 + 沙箱方案选「外置沙箱包裹 seam」);checker = 我。价值:北极星「安全层沙箱」欠账的务实、可确定性测、不违铁律解法 —— 真 OS 隔离交平台,内核只提包裹接缝。

## 做了什么

- **Config `sandbox_cmd: Option<String>`**(serde-default;模板,`{cwd}` 占位)。
- **纯核**(agent lib,离线可测):
  - `sandbox_split(s) -> Vec<String>`:引号感知分词(`"..."`/`'...'`/裸词)。
  - `sandbox_argv(sandbox_cmd, user_cmd, cwd) -> Vec<String>`:split → `{cwd}` 替换 → **user_cmd 作最后单个 arg 追加**。
- **`tools::run_argv(argv)`**:`Command::new(argv[0]).args(argv[1..])` 直执,**不经 cmd/sh** → user_cmd 原样进用户包裹器的解释器,免跨平台二次引号地狱。
- **接线**:`execute_tool_call` run_shell 分支,在**危险命令拦截 + 约束守卫之后**,配了 `sandbox_cmd` → `run_argv(sandbox_argv(...))`,否则 `run_shell`(宿主直跑,行为不变)。
- **进程全局** `SANDBOX_CMD: OnceLock`(`set_sandbox_cmd` set-once,与 HOOKS/ALLOW_JAILBREAK 先例一致);main.rs 启动装 `cfg.sandbox_cmd`。

## 为什么这样(对抗评审)

- **合铁律**:内核不引 OS 隔离 FFI(AppContainer/受限令牌/Landlock 均驳:重 FFI + 难确定性测 + 与「外置能力不进内核」张力大)。真隔离委托平台(docker/wsl),内核只提接缝——与仓内自述「真 OS 隔离是重量级件另议」一致。
- **argv 非 shell 字符串**:user_cmd 作独立 argv 元素传入,避 `cmd /C` 用 `"` 而 `sh -c` 用 `'` 的跨平台引号地狱(这是 Windows 主力下字符串模板 `{cmd}` 插值会踩的坑)。
- **纵深防御非替换**:危险命令拦截 + 约束守卫在包裹**之前**先过 —— 即便沙箱也先挡灾难命令(沙箱可能误配)。
- **默认零行为变化**:未配 `sandbox_cmd` → `active_sandbox_cmd()` None → 宿主直跑,既有 run_shell 语义与全部测试不变。

## 用法

config.json:`"sandbox_cmd": "docker run --rm -v {cwd}:/w -w /w alpine sh -c"`(或 `wsl`、自定义包裹器)→ 此后所有 `run_shell` 在容器内跑,写操作被容器隔离于宿主。留空 = 宿主直跑。

## 开放问题 / 下一步
