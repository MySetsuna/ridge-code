## 做了什么

### ① Hook 过危险拦截(补安全不变量)
- **缺口**:iter-40 的 `run_hook_command` 跑任意 hook shell **绕过** `is_dangerous_command` —— §8 不变量⑦「危险命令拦截不可绕过」在 hook 通道漏拦(`rm -rf /`、`mkfs`、fork 炸弹等)。
- **修**:纯核 `hook_is_safe(cmd) = is_dangerous_command(cmd).is_none()`;`run_hook_command` 起手命中灾难 denylist → **不执行 + 审计 `hook_blocked` + None**。hook 与 run_shell 工具**同守**这条硬线。

### ② 顶层 key 解析收敛(减法)
- **缺口**:顶层 key 解析(env→内联→key_env→auth)在 `real_provider`(前 3 档)与 `current_api_key` **各写一遍**,发散风险。
- **修**:抽 `resolve_top_level_key(cfg, auth)` 单一纯核;`real_provider` 前 3 档 → 一行调用,`current_api_key` → 一行调用。净删两处重复档逻辑(main.rs 前 3 个 `if let` 块 → 1 个;tui.rs 3 档 → 1 行);`main.rs` 顺带移除变为未用的 `resolve_key_env` 导入。

## 对抗评审战果(正确性门禁)
- **不变量回归优先于堆功能**:连加五轮后主动审最近所加,揪出**自己引入**的安全不变量违背并修 —— 这是 checker 的本分,比再加功能更值。
