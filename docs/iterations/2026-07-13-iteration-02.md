## 1. 本迭代做了什么

按 NotebookLM 指导「先建物理闭环」,补齐工具链与 provider 边界,让 agent 从「脚本假信号」走向「真实工具 + 结构化工具调用」。

### P0 —— `crates/tools`(真实工具集,std-only 跨平台)
- `read_file` / `write_file` / `run_shell`(Windows `cmd /C`,其余 `sh -c`),`ShellResult{code,stdout,stderr}` + `success()`。
- 接进 agent:`shell_tool()` 把 `run_shell` 包成 `Tool`。
- ⚠ M1 阶段**无沙箱**,只喂受控命令。

### P1 —— `crates/provider`(LLM provider 边界)+ agent 结构化 tool_call
- `LlmProvider` trait(`async fn complete`),统一内部表示:`Message`/`Role`/`ToolSpec`/`ToolCall{name,arguments:Value}`/`Completion`。
- **归一化**:`openai::parse_response`(`tool_calls[].function.arguments` 是 JSON **字符串**,解开)与 `anthropic::parse_response`(`content[]` 里的 `tool_use` 块,`input` 已是对象)—— 两种 wire 格式解析成**等价 ToolCall**,纯函数离线单测。
- `ScriptedProvider`:离线按序吐预设 `Completion`,站位真实 LLM,零联网。
- agent 新增 `build_llm_agent(provider)`:`reason` 问 provider 要结构化 tool_call → `act` 用 `execute_tool_call` 调**真实** `tools` → `verify` 认确定性信号(`exit 0` / `passed`)。`builtin_tool_specs()` 暴露 run_shell/write_file/read_file 给模型。
- 两条路径(scripted 大脑 / llm provider)**共用** `reason_route`/`verify_route`/`verify_node`/`tool_output_ok`,maker≠checker、双保险停机不变。

### 质量闸
- `cargo test --workspace`:**17 项全绿**(langgraph 6 + agent 5 + provider 2 + tools 3 + doctest 1)。
  - 关键新测:`openai_and_anthropic_normalize_to_same_tool_call`(归一化)、`execute_tool_call_writes_real_file`(结构化调用→真实文件)、`llm_agent_drives_real_tools_to_approved`(provider→真实 shell `exit 0`→approved,端到端)。
- `clippy -D warnings` / `fmt --check`:干净。
