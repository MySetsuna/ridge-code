# Iteration 31 报告 —— 视觉与状态双栏(输出分隔 / ctx% / 忙碌粘条)

> maker = 用户需求原文第 3、5、6 条。checker = CONTRACT-iteration-31。计时/计量特性一律纯格式化函数验收,零 wall-clock/PTY。

## 做了什么

**需求 5(输出块间隔)** —— `flush_commits` 每块前置一空白分隔行(`commit_height + 1`,渲染 `Line::default()` 打头),连续输出块(命令回显/事件/终答/todo/结果)不再贴成一片。

**需求 3(ctx% + 自定义底栏 + 更显眼)**:
- 顶状态行加 `ctx N%` 段;busy 时 `RidgeCode` 徽标转暖色(Yellow),空闲 Cyan —— 一眼辨运行态。
- 输入框**下方**新增自定义底栏:`config.status_bar` 模板串渲染,占位 `{provider}{model}{ctx}{tokens}{cwd}`,留空用内置 `DEFAULT_STATUS_BAR`。
- ctx% 分母 = `meta.ctx_window`(默认 `DEFAULT_CTX_WINDOW=200_000`,`/models` 命中当前模型即缓存其真实上下文窗口);分子 = 当前 history 的 `est_tokens` 估算和。

**需求 6(忙碌粘条)** —— 输入框**上方**新增粘性行(仅 `ui.busy` 时有高度):`⚡ {phase} · ⏱ {读秒}s · {tok} tok · {tok/s} · todo d/n`。流式 token 经 `est_tokens` 实时累计(`ui.stream_tokens`,token_rx 每块累加),`task_started: Instant` Submit 置、done/中断清 —— 读秒与速率据此算,`Instant` 属 app 运行时(非 Workflow 脚本),允许。

**布局** —— `draw` 改五槽定长(顶行 / 输出尾 `Min(1)` / 忙碌槽 `Length(0|1)` / 输入框 / 底栏);忙碌槽空闲高 0,索引恒定。视口 `LIVE_HEIGHT=14` 足容(峰值约 11 行)。

**接缝** —— `est_tokens` 提 `pub`(lib.rs;显示层 ctx% 复用同一估算口径,不另造 tokenizer)。`Config.status_bar: Option<String>`(serde default)。`ReplMeta` 加 `status_bar`/`ctx_window`。

## 对抗评审战果(正确性门禁)

- **计时纯函数化**:`token_rate`/`fmt_busy_bar`/`ctx_percent` 全收数值入参,读秒/速率的时钟采样留在主环(`Instant::elapsed`),测试零 wall-clock —— 规避 NLM 惯犯的 sleep/ms 断言。
- **概念放对层**:ctx% 复用既有 `est_tokens`(内核精简铁律:不引 tiktoken),`Instant` 是 app 运行时非脚本禁区,`unicode-width`/token 估算均显示/估算层,未污染引擎。
- **诚实边界**:「读秒」= 正计秒表(总时长无从得,不伪造倒计时);token 速率标注为 `est_tokens` 估算,非 provider 计费口径。
- **最小面**:逻辑光标/流式尾巴/审批模态/补全浮窗零改;布局定长五槽索引恒定,`draw` 唯一调用点已改签名,无遗漏 caller。
