# Iteration 38 报告 —— 真正接入内置供应商:交互式登录页 + 连接校验

> maker = 用户需求「真正接入内置供应商,并且可以登录」→「交互登录页 + 连接校验」。checker = CONTRACT-iteration-38。价值门禁不适用(用户明确需求)。

## 做了什么

### 连接校验(登录先验证再落盘)
- `verify_key_via(&dyn HttpClient, kind, base_url, key) -> Result<usize,String>`:经 `provider::models::fetch_models` 打 `{base_url}/models` 鉴权 GET,Ok→模型数、Err→原因。**HttpClient 接缝可离线测**。
- `verify_provider_key(kind, base_url, key)`:真 `ReqwestClient` + 15s `timeout` 包壳。
- **正确性关键**:`ReqwestClient::get_json` 对非 2xx 返 `Err("http {status}…")`,`fetch_models` 用 `?` 透传 → **错 key / 坏端点如实失败,不落盘**(隔离核实)。
- CLI `login` 默认校验(`verifying …` → `✓ connected (N models)` / `✗ … nothing written`);`--no-verify` 跳过(离线配 / 不支持 `/models` 的端点兜底)。`run_login` 改 `async`。

### 交互登录页(TUI)
- `PanelKind::Login` + `login_panel()`(14 家 preset,id·label·model,可搜索)。
- `/login`(无参)开页;↑↓ 选一家 → Enter 进 key 输入态(`panel_enter` 的 `(Login,None)` 分支,标题提示选了哪家)→ 输入 **掩码 `•`**(`draw_panel` 对 Login+editing 掩码,防肩窥)→ Enter 提交。
- **提交走主环唯一异步 Enter 分支**(校验需联网,`panel_enter` 是同步的):`login_apply_verified` = 校验 → 成功写 auth+config(`tui_login`)+ 热切 + `✓ connected · now active` + 关页;失败 `✗ …` 留输入态可重试。
- `/login <id> <key>` 快捷路径同走 `login_apply_verified`(同样校验)。`/login list` 列内置。

## 对抗评审战果(正确性门禁)

- **校验语义先自证再用**:代码索引核 `get_json` 非 2xx 返 Err → 确证「错 key 报失败」成立才把 `/models` 当校验器,不臆断。
- **异步分支最小化**:仅 Login 的 key 提交需异步(联网校验),其余 Enter 仍走同步 `panel_enter` —— 一处 `matches!` 判定分流,不把整个 panel_enter 异步化(避免连锁改所有 Panel 路径)。
- **校验可离线测**:复用既有 `HttpClient` 接缝 + stub,零网络/PTY/wall-clock 断言校验映射;文件写入沿用 iter-37 已测的 apply_login/auth。
- **不重复造轮**:登录页复用 iter-35 Panel 框架(rows/filter/editing/draw_panel),仅加一 kind + 掩码分支;校验复用 iter-29 `fetch_models`。
