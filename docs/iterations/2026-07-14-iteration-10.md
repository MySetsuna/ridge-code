## 3. web 工业级研究闭环(本轮重点)

- **`fetch_url`**:抓网页 → `html_to_text`(删 script/style/head、块级转行、去标签、压缩、截断)→ 补全 **`web_search → fetch_url → 据原文作答`** 的 RAG 闭环。
- **无 key 多引擎 fallback**:用户明确**不接 Brave/Tavily 付费 API**。改为有序引擎链(International=[duckduckgo,bing]、Restricted=[bing-cn]),某引擎报错/空 → 自动落下一个;全程无 key 直抓 HTML。过滤 DuckDuckGo 广告位脏链。
- **网络探测多探针**:并发探 google+gstatic,3s 超时,任一通即直连,更抗抖动。
- 结果去重。

## 4. 插件式扩展(北极星实证)

- **`~/.ridge/config.toml`**:一处配 provider/model/base_url/预算/多 `[[mcp]]`/skills_dir/skip_danger,env 覆盖;**密钥不进 config,只走 `RIDGE_API_KEY` env**。GLM 实测:仅给 key,其余全来自 config。
- **多 MCP 并接**:config 里多个 `[[mcp]]` + 兼容旧 env 单 server。
- **AnySearch 调研实证**:AnySearch(结构化搜索 MCP server)**零改源码**接入 —— config 加 `[[mcp]]` 即得 `anysearch__search/extract/batch_search/get_sub_domains`。**实测接入成功**。这印证了「加能力 = 加 MCP 配置,不改 Rust 源码」。结论:内置零依赖当默认,AnySearch 当可选结构化升级。
