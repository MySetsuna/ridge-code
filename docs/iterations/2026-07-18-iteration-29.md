## 背景(本轮定位)

用户对交互体验判「半成品玩具」,提六条需求;最重(P0)为「像 opencode 一样内置多 provider、经各自 base_url **实时抓模型信息(尤其上下文大小)**、程序内增/切/自建」。经代码索引核实:provider 档案/热切换/`config_add_provider` 已在,唯缺**实时模型列表 + context size + 程序内 `/provider add`**。本轮补此三缺口。其余五需求(补全 ↑↓/wcwidth 光标/输出分隔/状态双栏)排 iter-30+。

## 做了什么

- **`provider::models`(新模块)**:
  - `ModelInfo{id, context: Option<u64>}`。
  - `parse_model_list(&Value) -> Vec<ModelInfo>` —— 纯函数,兼容 OpenAI/OpenRouter/Anthropic 的 `{"data":[..]}` 与顶层数组;坏/空 → `vec![]`(优雅降级)。context 多路探测:`context_length`/`context_window`/`max_context_length`/嵌套 `top_provider.context_length`。
  - `fetch_models(http, kind, base_url, key)` —— 按 kind 造鉴权 header(openai=Bearer,anthropic=x-api-key+version),GET `{base_url}/models` → 解析。抓取走注入的 `HttpClient` 接缝。
- **`HttpClient::get_json(url, headers)`**:对称补 `post_json`,**默认 `Err("unsupported")`**(既有替身零改动),仅 `ReqwestClient` 真实现(reqwest GET)。
- **`agent::parse_provider_add(args) -> Result<ProviderProfile>`**:纯函数,解析 `<name> <kind> <model> <base_url> [key_env]`;未知 kind/缺参 → Err;`api_key=None`(明文永不落盘)。
- **TUI 命令(`run_command` 改 `async`)**:
  - `/models`:解析当前 key(env `RIDGE_API_KEY` → config 顶层 `api_key`)→ `fetch_models`(裹 15s `timeout` 防挂)→ 列 `id (ctx 200K)`,`→` 标当前 model。
  - `/provider add ...`:接 `parse_provider_add` + 既有 `config_add_provider` + 写盘;成功提示切换命令 + 密钥设哪个 env。
  - `/models` 入 `SLASH_COMMANDS` 补全表;`/help`、`/model`、`/provider` 提示同步更新。
  - `fmt_ctx`(人读上下文)、`current_api_key`(key 解析)纯函数辅助。

## 对抗评审战果(正确性门禁)

- **概念放对层**:模型抓取的 HTTP 出口选 `HttpClient::get_json`(带 header 的鉴权 GET)而非无 header 的 `WebFetch::get_text` —— 模型端点必须鉴权。
- **密钥安全不回退**:`/provider add` 走 `parse_provider_add`(`api_key=None`)+ `config_add_provider`(`skip_serializing`),双保险明文永不落盘;测试断言 `!out.contains("api_key")`。
- **优雅降级**:context size 只取端点自报,缺失显示 `ctx ?`,不臆造(未接 models.dev 式付费静态目录)。
- **网络不进测试**:真 `/models` 抓取是 runtime 行为,仅纯函数 + `StubGet` 替身覆盖(遵「计时/网络类不作验收信号」铁律)。
