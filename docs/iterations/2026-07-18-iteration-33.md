# Iteration 33 报告 —— 允许输入排队(busy 时可提交,任务毕自动接跑)

> maker = 用户需求「允许输入排队」。checker = CONTRACT-iteration-33。

## 做了什么

- **busy 时 Enter → 入队**:`InputAction` 加 `Queue`;`input_action` 里 `Enter if busy => Queue`、`Enter => Submit`(去 `!busy` 卫,`busy` 仍被 `Queue` 臂消费)。`Ui` 加 `queued: VecDeque<String>`。
- **统一提交点**(iter-33 核心):主环顶新增 `!ui.busy && pending_submit` 消费块 —— `run_command`(斜杠即时)或起后台任务。原 Submit 键臂内联的起任务逻辑**上移至此唯一处**,键 `Submit` 臂缩为 `pending_submit = Some(input)`,消除重复。
- **任务毕自动接跑**:`done` 臂尾 `if pending_submit.is_none() { pending_submit = ui.queued.pop_front(); }` → 下一圈顶点起下一任务。
- **中止清队**:`Interrupt` 臂 `ui.queued.clear()` + `pending_submit = None`,note 附清空条数 —— 中断即取消全部待跑,不意外接跑。
- **反馈**:忙碌粘条 `fmt_busy_bar` 加 `queued` 参,>0 追加 ` · ⏳N`(`Vitals.queued` 传 `ui.queued.len()`);入队时 note「⏳ 已排队(N 条待跑)」。

## 测试状态(确定性验收,全达成)

`cargo test --workspace && cargo fmt --all --check && cargo clippy --workspace --all-targets -- -D warnings` 全 **exit 0**(ridgecode 35)。改/增:
- `input_action(Enter, busy=true) == Queue`(原断言 `Ignore` 改;`busy=false == Submit` 不变)。
- `busy_bar_shows_queue_depth`:`queued=0` 无 `⏳` 段、`queued=2` 含 ` · ⏳2`。

## 对抗评审战果(正确性门禁)

- **消除重复而非新增**:起任务/跑命令逻辑从键臂上移为**主环顶唯一处**,键入提交与队列接跑共用一条路 —— 净新增行少、无两份可漂移的 spawn 码。
- **无 fn 巨签名**:借 `pending_submit: Option<String>` 状态变量 + loop-top 消费,避开把十余个 clone/借用塞进一个 `async fn` 的丑签名(ponytail:最简结构达标)。
- **中止语义安全**:中断清空队列,防「abort 后排队项仍接跑」的意外副作用(信任边界:用户中止 = 取消全部)。
- **验收纯函数化**:`input_action`/`fmt_busy_bar` 均纯函数直断言,零 PTY/wall-clock。
