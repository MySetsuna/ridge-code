## 1. 本迭代做了什么

NotebookLM 结合 51 源给出「未实现方向」排序:①**标准存储库** ②成本记账+硬预算熔断 ③子agent并行 ④Cron/Webhook。经对抗评审(见 §4)选 **①标准存储库**——源力最强(被称「系统的心脏 / 持久化脊柱」)、离线可确定性验收、属运行时持久化(内核适配,不违「外置能力走 MCP」铁律)、且**确未实现**(现状仅平铺 `trace.json` 每轮覆盖=丢历史)。

**Ponytail 收窄**——只做真正被产出的最小版,不建空脚手架:

- **`write_run(out, run_dir)`**(`crates/agent/src/lib.rs`):把一轮任务落成 `<run_dir>/manifest.json`(结构化结论)+ `trace.json`(完整审计轨迹,复用既有 `write_trace`)。相比旧的「cwd 平铺 `trace.json` 每轮覆盖」,**每 run 独立目录 → 审计历史不再互相冲掉**,是跨 run 复利的物理底座。
- **`HaltReason` 枚举 + `halt_reason(&AgentState)`**:据终态确定性判定「为什么停」——`approved`(成功)/ `budget_exceeded` / `no_progress` / `step_cap` / `unverified`。这补齐了预算熔断此前唯一缺的一环:**响亮失败信号**(loop engineering 反复强调 "fail loudly, not at token prices all night")。`is_success()` 供调用方给非零退出码用。
- **接线**(`crates/agent/src/main.rs`):`trace_and_report` 改写到 `.ridge/runs/<纳秒 id>/`(cwd 本地,像 `.git` 随项目走),非成功时 stderr 明确播报停机原因。
- **不做**:来源提到的 `signals/`(跨 loop 复利单元)**暂无产者**,故不建空目录(YAGNI);源码留升级路径注释。
