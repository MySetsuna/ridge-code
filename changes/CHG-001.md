# Make OAuth profile persistence testable without process-global config races

Extract the config-path part of OAuth profile registration behind a path-aware
internal helper. Keep the public runtime entrypoint environment-driven, while
the regression test writes its isolated temporary config directly instead of
mutating process-global `RIDGE_CONFIG` during the parallel test suite.
Also keep the repository's SpecTree/Obsidian projection usable when the
workflow contains a draft change: generated change notes must be exported and
generated `.spectree` approval/evidence state must not be treated as an
unmapped source file.

Acceptance:

- OAuth profile registration still writes one `use_oauth` profile without an
  inline API key.
- The focused regression test passes under the default parallel test runner.
- `npm run spectree:export` and `npm run spectree:check` remain aligned with a
  draft change and its approval state.
- `cargo test --workspace` and `cargo clippy --workspace --all-targets -- -D warnings`
  pass.
