# 分诊技能

面对一堆乱糟糟的待处理项,先理清再动手(loop-engineering 的 triage 环):

1. **收集事实**:`run_shell` 看构建/测试输出、`search`/`read_file` 找相关代码、`web_search` 查陌生报错。别凭猜。
2. **归类去重**:把 N 条现象归并成几个**根因**(一个根因常引发多条报错),标出重复项。
3. **排优先级**:按「影响 × 修复成本」排。阻塞编译/测试的 > 功能 bug > 告警 > 优化。
4. **列成清单**:超过两项就 `todo_write` 列出来,写清每项的**下一步动作**(具体到文件/命令),别只写「修一下」。
5. **交回决策**:自己能顺手修的小项直接修;拿不准取舍的,列清利弊交给用户拍板,不擅自做大改。
